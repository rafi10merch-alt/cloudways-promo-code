## Country pages (geo-SEO — build after core clusters, avoid doorway pages)

Per the brief: **do not** create near-duplicate country pages that only swap the country name. Instead, each country page should add genuinely different information — local payment methods, data-center latency from that region, currency display, and any region-specific promotions.

Planned slots: `/us/cloudways/`, `/uk/cloudways/`, `/ca/cloudways/`, `/au/cloudways/`, `/in/cloudways/`, `/pk/cloudways/`, `/ae/cloudways/`, `/de/cloudways/`, `/fr/cloudways/`, `/es/cloudways/`, `/it/cloudways/`, `/br/cloudways/`.

Each should:
- Use `hreflang` tags pointing to sibling country pages and a `x-default` pointing to `/cloudways/pricing/`.
- Reference the nearest Cloudways/provider data center region and realistic latency expectations.
- Note local currency display (Cloudways bills in USD regardless — say so explicitly to avoid misleading pricing claims).
- Canonical to itself (not to the US/default page) since content genuinely differs — that's what keeps this from being a doorway page.
